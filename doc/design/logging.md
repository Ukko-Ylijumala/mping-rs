# In-memory logging

There is no external log file. All status, debug, and error messages are
recorded in an in-memory ring buffer (`MessageBuffer`) and surfaced two
ways: as a stderr stream filtered by level, and as a Ratatui popup
toggled with F12.

## `MessageBuffer`

Lives in `src/logging.rs:212`. Owned by `MpConfig.buf` during startup,
then by `AppState.logger` (an `Arc<MessageBuffer>`) once the app is
built — every component clones the `Arc` to log.

```text
MessageBuffer {
    buf:        RwLock<VecDeque<Message>>,   // fixed capacity ring
    cap:        usize,                       // default 1024
    total:      AtomicU32,                   // ever-pushed counter
    to_stderr:  LogLevel,                    // stderr threshold, default Notice
}
```

Push semantics: when the deque is full, the oldest is dropped before the
new message is pushed (`logging.rs:237-247`). The displayed count
(visible in the log popup title) is `len()`; the lifetime count
(`total`) is incremented on every push and exposed for stats purposes.

## Levels

`LogLevel` (`logging.rs:25-37`) follows syslog convention but with
`Trace` added at variant index 15:

```text
Emergency < Alert < Critical < Error < Warn < Notice < Info < Debug < Trace
```

The `Ord` derive is wired so `if msg.lvl <= self.to_stderr` writes
higher-priority messages to stderr (`logging.rs:244`). Lower priority
(`<=` in the enum-order sense) means *higher* severity here because of
how the variants are declared — `Emergency` is "lowest" (most severe).

By default the buffer prints `Notice` and above to stderr. `--verbose`
lowers the threshold to `Info`; `--debug` lowers it further to `Debug`
(`args.rs:189-198`).

## Method generation via macros

The per-level convenience methods (`error`, `warn`, `info`, `debug`,
`trace`, etc.) on `Message`, `MessageBuffer`, and the `Logger` trait
are generated by three macros (`logging.rs:60-114`):
`gen_level_methods_msg!`, `gen_level_methods_buf!`,
`gen_level_methods_trait!` + `gen_level_methods_impl!`. They share a
`level_variant!` mapper that converts a function name like `debug` to
`LogLevel::Debug`. Adding a new level means adding a `level_variant!`
arm and including the new name in the four macro invocations.

## Display

Each `Message` carries a `TimeSinceEpoch` timestamp from the
`timesince` crate. `Message::as_line()` (`logging.rs:156`) returns a
styled Ratatui `Line` with the message coloured by level (red for
Error, yellow for Warn, cyan for Notice, dim for Debug, etc.). The log
popup renders the buffer via `MessageBuffer::to_list()`
(`logging.rs:301`), which iterates and produces one `Line` per
message.

A subtle detail: `Message::as_line()` clones the inner string into the
returned `Span` so the produced `Line` doesn't borrow from the buffer.
This matters because the renderer needs the list to outlive any read
lock taken while building it.

## The `Logger` trait

`Logger` (`logging.rs:326-342`) is the abstraction shared between
`MessageBuffer` and other producers that want to log without taking a
direct dependency on the buffer type — `parse_ip_addresses`,
`resolve_names`, and the rest of the target-parsing pipeline are
generic over `T: Logger`. The trait impl on `MessageBuffer` routes
through the level-specific methods and returns the timestamped string
representation, which lets callers reuse the formatted text without
re-formatting.

## Coordination with the TUI

While the TUI is on the alternate screen, writes that would otherwise
go to stderr are gated by `ALT_SCREEN_ACTIVE`. The `eprintln_nomangle!`
macro (`src/macros.rs`) routes through `eprintln_safe`
(`src/ui/tui.rs:881`) which suppresses output when the alt screen is
active. That way:

- Before TUI startup: messages above the threshold appear on stderr
  immediately.
- During TUI: nothing prints to stderr; the user reads the log via F12.
- After TUI teardown: stderr is restored and any deferred messages from
  signal handlers (etc.) print normally.
